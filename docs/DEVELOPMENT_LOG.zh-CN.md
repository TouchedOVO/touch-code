## 2. 里程碑设计与实现细节

### M1 环境与接口适配
- 构建 `space-code-agent` 规范包结构，建立全局配置中心（统一管控步数上限、费用配额、文件尺寸与重试机制）及事件总线模型。
- 实现 `DeepSeekProvider` 适配器：对齐官方 Responses API，原生支持 `reasoning.effort` 深度推理与工具调用（Function Calling）；内置针对 HTTP 429/5xx 网络异常的指数退避重试，针对 401/403 鉴权异常即时熔断并脱敏摘要。
- 研发 `SecretRedactor` 脱敏引擎：基于注册密钥及 `sk-*`/Bearer 正则双重匹配机制，在 GUI 显示及日志中实施安全掩码。
- 完成 PySide6 主界面第一版：集成模型配置、思考强度调整、文档选定、工作区配置、执行控制与实时状态显示；优化 Qt 控件生命周期管理。
- **技术指标**：包含 10 个 Python 模块、968 行源码；通过 11 项单元测试，完整覆盖请求 Schema 校验、协议解析与退避重试逻辑。

### M2 文档解析与需求归一化
- 强化 Markdown 解析：支持 39 个章节分级、4 张数据表与 10 个代码块的结构化抽取；内置 UTF-8 编码及 BOM 校验。
- PlantUML 语义解析：支持提取全部 13 处 UML 定义块，覆盖类图、时序图、用例图、组件图等 11 类标准软件架构视图；结构化解析参与者、接口、消息时序与状态变迁。
- 语法容错与设计冲突识别：针对架构图表中的非标准符号实施低危冲突记录并平滑降级，建立跨视图冲突矩阵与设计假设记录。
- 归一化需求模型：抽取 3 条显式功能需求、3 条用例图推导需求及 ASR 质量属性约束；构建包含 4 个核心组件、8 项设计冲突及 8 条假设的领域模型。
- **技术指标**：完成 516 行基准文档的高保真解析；提取 7 项核心需求与 11 类架构视图；累计通过 28 项自动化测试。

### M3 受控 Agent 状态机循环
- 实现 8 项原子化工具：`list_files`、`read_file`、`write_file`、`replace_in_file`、`search_in_files`、`inspect_project`、`run_tests`、`finish_task`；强制要求 JSON Schema 参数校验，输出结构化错误。
- 确立 `WorkspacePolicy` 安全沙箱：严格拦截绝对路径、Windows 盘符、UNC 路径、保留设备名及符号链接越权；基于临时文件与 `os.replace()` 实现原子写入，严防写入破坏。
- 任务编排调度（Orchestrator）：实施严格的步数配额、费用预算、超时限制与任务取消机制；要求任务完成声明必须通过交付校验门禁。
- 结构化可观测性审计：会话全过程沉淀为 `.agent_state/<session>/events.jsonl`、`tools.jsonl` 与 `history.jsonl` 审计流。
- **技术指标**：拦截 11 类典型路径越权注入攻击；通过 68 项自动化测试用例。

### M4 任务规划与项目生成
- 设计基于强类型的任务规划器（Planner）：严格约束大模型输出 `ProjectPlan`，包含组件拆解、文件结构、需求追溯映射与技术偏差说明。
- 全局控制器（Controller）状态机：流转链路规范化为 `VALIDATING_INPUT → NORMALIZING → PLANNING → IMPLEMENTING → VERIFYING → REPORTING`。
- 构建零外部依赖基准工程（Space Fractions）：实现学生端、教师端、数据持久化与服务交互模块，配套提供 19 项 Node.js 单元与端到端测试。
- 多维追溯机制：建立“任务规划声明 + 源码 `Covers:` 注解 + 交付文档分析”的三维追溯网络。
- **技术指标**：基准样例工程包含 34 个源码文件 / 2632 行代码；Mock 状态下 36 步完成全量代码输出；需求覆盖率达成 100%；全量测试验证通过。

### M5 质量验证与自愈闭环
- 多层级静态质量分析：覆盖目录完整性、JSON 语法、Python AST 合法性、JavaScript 语法树分析（`node --check`）及需求覆盖一致性。
- 交付准入校验（DeliveryValidator）：对核心交付物（说明文档、依赖声明、自动化测试、架构假设说明）进行完备性强校验。
- 受限测试执行器：仅开放预设白名单命令，执行前需人工确认授权；限制最长执行时限为 300 秒并实施环境变量隔离。
- 自愈修复反馈机制：当交付校验未通过或测试失败时，捕获结构化报错并触发最多 3 轮定向修复状态机。
- **技术指标**：静态检查项在基准用例中 100% 通过；有效验证测试失败自愈流程与超限平滑降级机制。

### M6 GUI 交互与分发打包
- 异步线程解耦：采用 `QThread` 承载 I/O 密集型与模型通信任务，主界面主事件循环保持毫秒级响应；通过 `ApprovalBridge` 安全调度跨线程人工审批对话框。
- 实时态势可视化：界面动态展示当前执行阶段、任务清单、实时审计日志、生成文件清单（含大小与 SHA-256）及真实 Token 统计。
- 二进制打包发布：基于 PyInstaller 配置文件构建自包含可执行程序，内嵌样例资产、图标与应用元数据。
- **技术指标**：单文件 `SpaceCodeAgent.exe` 体积控制为 58.2 MiB；冷启动耗时 3.1 秒；无头 CLI 冒烟测试及端到端自动化 GUI 测试全部通过。

### M7 交付验收与发布归档
- 完成自动化测试体系收敛：84 项 pytest 用例全绿通过；基准工程 19 项 Node.js 测试全量通过。
- 真实大模型调用验证（T14）：接入真实 `deepseek-v4-pro` 模型端点，消耗 75 轮交互与 114 次工具调用，成功生成具备状态持久化及前端界面的完整项目，27 项配套测试与浏览器端 E2E 验证全部通过（详细证据归档于 `docs/evidence/t14-real/`）。
- 干净环境验证（T15）：在剥离 Python/Qt 的宿主测试机与 CI Runner 中完成二进制包冒烟与端到端代码生成检验。

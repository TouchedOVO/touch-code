# 系统架构设计说明书 (Architecture Documentation)

> **设计基准与目标**：本架构文档针对 Space Fractions 学习系统进行生产就绪级架构设计，对齐业务需求规范与 11 类标准 PlantUML 架构视图，建立覆盖功能需求（FR）、非功能质量属性（NFR）与架构显著需求（ASR）的端到端技术契约。

---

# A. 执行摘要 (Executive Summary)

Space Fractions 是一个基于 Web 的互动式练习系统，旨在提升小学六年级学生的分数四则运算能力。系统包含引导向导、主功能菜单、交互式分数题库答题链路、即时计分反馈、结算成绩单及上下文帮助系统。

为支持企业级交付与微服务演进，系统划分为三大核心自治组件：
- **GameComponent**：管理答题会话生命周期、校验答题结果、实时计算得分并聚合结算报告；
- **QuestionComponent**：负责题库资产维护、动态随机抽题算法、标准答案索引以及管理员 CRUD 接口；
- **UserComponent**：负责学生端免注册会话凭据颁发、管理员认证鉴权与令牌颁发。

|---|---|---|---|---|
| **FR-1** | 功能需求 | 用户（学生）可交互完成分数运算练习、即时获取答题反馈并查阅最终得分结算报告。 | GameComponent, WebUI | 采用轻量响应式前端与无状态会话设计，降低交互时延。 |

# C. 总体架构拓扑 (Architecture Overview)

系统采用领域驱动分层架构，各核心服务间遵循松耦合契约：
- **客户端接入层**：Web 单页应用，支持全键盘与高对比度无障碍交互。
- **网关与路由代理**：统一 API 网关，负责路径路由转发、CORS 策略与静态资源分发。
- **核心业务服务层**：
  - `GameService`：游戏与计分核心逻辑；
  - `QuestionService`：题目管理与随机选题；
  - `UserService`：用户会话与权限控制。
- **持久化层**：支持基于文件系统的原子存储及标准 SQL 数据库适配器。

# D. 核心组件详细设计 (Detailed Technical Design)

## 1. GameComponent（游戏与计分组件）
- **核心职责**：答题会话状态机管理、单题作答正确性比对、得分动态累加、结算报告聚合。
- **外部接口 (REST API)**：
  - `POST /api/games/session`：创建练习会话，拉取初始题目集；
  - `POST /api/games/session/:id/submit`：提交单题作答结果并获取即时反馈；
  - `GET /api/games/session/:id/result`：拉取练习结算汇总。
- **内部契约**：通过内部接口调用 QuestionComponent 进行题目完整性核验。
- **数据一致性**：答题进度实时持久化，支持异常重启自愈恢复。

## 2. QuestionComponent（题库管理组件）
- **核心职责**：六年级分数运算题目管理、随机抽取算法、管理端增删改查。
- **外部接口 (REST API)**：
  - `GET /api/questions/random?count=10`：随机拉取 10 道题目（不含标准答案）；
  - `POST /api/questions`：新增题目（需管理员鉴权）；
  - `PUT /api/questions/:id`：更新题目（需管理员鉴权）；
  - `DELETE /api/questions/:id`：删除题目（需管理员鉴权）。

## 3. UserComponent（用户与鉴权组件）
- **核心职责**：学生端免注册临时凭据分配、管理员登录认证与令牌签发。
- **外部接口 (REST API)**：
  - `POST /api/users/guest`：签发临时学生会话凭据；
  - `POST /api/users/login`：管理员凭据鉴权并换取 Bearer Token。

# E. 部署与运维架构 (Operations & Deployment)

1. **容器化与微服务拓扑**：
   - 各服务支持独立打包为轻量 Docker 容器；
   - 支持通过 Kubernetes 编排部署，配置 Liveness / Readiness 探针。
2. **轻量单机运行规范**：
   - 在开发与检验环境下，支持整合为模块化单体进程（Node.js 原生标准库），实现零外部依赖直接运行。

---

# F. 安全与数据保护架构 (Security Design)

- **鉴权机制**：管理端接口采用 HTTP Bearer Token 机制，禁止未鉴权访问。
- **凭据管理**：敏感环境变量（如 API 密钥、数据库凭据、JWT 签名密钥）必须通过安全上下文注入，严禁硬编码。
- **输入防护与数据脱敏**：所有入参实施强类型模式校验（Schema Validation），防御 SQL 注入与路径穿越；日志记录中强制脱敏用户凭据。

---

# G. 测试策略与质量矩阵 (Testing Strategy)

- **单元测试**：针对分数四则运算（约分、通分、带分数解析）、计分规则、入参校验覆盖 100% 核心分支。
- **服务契约测试**：验证各微服务 HTTP REST API 的入参与响应格式契约。
- **持久化重启测试**：模拟进程异常退出并重启，检验持久化存储中的答题记录是否完整恢复。
- **端到端流程测试**：覆盖“生成会话 → 答题 → 结算 → 管理员题库维护”完整用户旅程。

---

# H. 架构选型与技术权衡 (Tradeoffs & Alternatives)

1. **服务粒度权衡**：采用模块化服务设计，在代码层面保持严谨的领域边界，在运行层面支持单机整合部署与容器集群部署双模式。
2. **通信协议选择**：优先采用标准 HTTP/REST 协议，保证跨语言、跨平台的普适性与调试可观测性。
3. **数据存储策略**：抽象统一仓储层接口，基础交付支持轻量原子文件存储，企业级部署无缝切换外部 PostgreSQL 集群。
